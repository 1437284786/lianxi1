# 内部资料保密规则

## 1. 保密级别

| 级别 | 定义 | 仓库处理规则 | 外部营销默认权限 |
|---|---|---|---|
| `public` | 经授权可公开的资料或字段 | 可在公开仓库保存，但仍需保留来源、版本和批准记录 | 仅在内容本身也已批准时允许 |
| `internal` | 仅供企业内部协作的普通经营/技术资料 | 公开仓库只放必要的非敏感结构或索引；原件优先放受控存储 | 不允许 |
| `confidential` | 敏感经营或技术资料 | 不得将原件、完整内容或可逆推细节提交公开仓库；仅登记脱敏索引 | 不允许 |
| `restricted` | 客户身份、配方、价格、成本、密码、密钥等严格受限资料 | 不得进入公开仓库；仅在最小权限受控系统处理，公开索引也不得暴露敏感内容 | 不允许 |

保密级别与数据是否真实、是否批准是不同维度。`public` 不等于 `confirmed`；`approved` 也不等于允许公开。

## 2. 强制规则

1. `confidential` 和 `restricted` 资料不得进入公开仓库。
2. 第一轮客户应用记录必须匿名化，只保留完成应用验证所需的行业、产品、粒度、应用、问题和结果。
3. 不保存客户或员工个人手机号、私人邮箱、身份证件、家庭地址或其他非必要身份信息。
4. 不保存密码、API 密钥、访问令牌、私钥或受控系统登录信息。
5. 配方、原料比例、价格、成本、客户名称和订单身份默认按 `restricted` 处理。
6. 内部资料不会因 Codex 读取、提取或整理而自动成为可公开营销资料。
7. 对外使用必须同时满足：数据已批准、保密级别允许、外部营销权限明确为 `yes`、引用范围未超出产品/粒度/批次/有效期。
8. 无法判断级别时先按更严格级别处理，并由资料所有人确认。

## 3. 客户资料匿名化最低要求

- 客户名称替换为内部不可逆编号，例如 `CUSTOMER-ANON-001`；映射表不得进入本仓库。
- 删除联系人姓名、电话、邮箱、账号、地址和可识别订单号。
- 国家信息只有在应用验证确有必要且不会识别客户时保留；本阶段不得据此开展国家排名。
- 价格、成本、折扣和付款条件删除或单独放在 `restricted` 系统。
- 附件图片、PDF 属性、页眉页脚、二维码、标签和文件元数据也必须检查并脱敏。

## 4. 泄露或误提交处理

发现敏感资料误入仓库时应立即停止传播，通知资料所有人和仓库管理员，评估 Git 历史清理、凭据轮换和访问审计；不得只删除工作区文件而忽略历史记录。
