# 企业资料导入指南

## 1. 企业准备和上传

1. 按 `department-questionnaires/` 由责任部门填写，不确定项留空或注明“待确认”，不得填行业常见值。
2. 每份文件标注产品、粒度、批次/时间范围、文件版本、出具日期、责任部门和建议保密级别。
3. 原件上传到企业指定的受控存储；公开仓库不得接收 `confidential` 或 `restricted` 原件。
4. 提供文件清单和受控位置，不要在聊天、提交信息或文件名中暴露密码、客户身份、价格或配方。
5. 收件人先进行病毒/可读性检查和脱敏检查，再进入登记流程。

## 2. 推荐文件命名

推荐格式：

`<product_id>__<document-type>__<grit-or-batch>__<YYYY-MM-DD>__<version>.<ext>`

示例格式（仅示范命名，不代表文件存在）：

`bfa-grade-1__coa__batch-code__2026-06-08__v1.pdf`

规则：

- 使用仓库中的合法 `product_id`；
- 日期使用 `YYYY-MM-DD`；
- 文件名不写客户名称、联系人、价格、配方或其他敏感内容；
- 同名修订使用明确版本，不用“最终版2”“new”等模糊名称；
- 原文件名若包含敏感信息，上传前生成脱敏副本，原件保留在受控系统。

## 3. 客户资料匿名化

- 使用不可逆匿名编号，客户身份映射由企业在仓库外保存。
- 删除姓名、手机号、私人邮箱、地址、社交账号、可识别订单号、合同价和付款条件。
- 只保留必要字段：客户行业、产品、粒度、应用场景、采购关注点、问题、投诉/退货原因、复购事实、所需文件和验证结论。
- 检查 PDF 元数据、Excel 隐藏表/批注、图片 EXIF、标签照片和页眉页脚。

## 4. 标明产品、粒度和批次

每条数据必须回答：

- 适用哪个 `product_id`；
- 适用哪个粒度体系和具体粒度；
- 适用哪个批次、日期区间或工艺版本；
- 是单批结果、典型值、内部控制限值还是对外保证值；
- 使用什么单位、抽样方法和测试方法；
- 是否适用于全部工厂/产线；
- 谁核实、谁批准、是否允许外部营销。

## 5. 各格式处理流程

### 扫描 PDF

1. 保留只读原件及文件哈希（哈希放受控索引）；
2. OCR 仅生成工作副本，标记可能识别错误的表格、上下标和小数点；
3. 人工逐页对照产品、批次、单位、方法、签章和有效期；
4. 敏感原件不得提交公开仓库。

### Excel

1. 保留原始工作簿，检查隐藏工作表、公式、批注、外链和宏；
2. 导出需处理的工作表为 UTF-8 CSV 工作副本；
3. 不把公式显示值误当成受控原始值；
4. 人工确认单位、合并单元格和空值含义。

### CSV

1. 使用 UTF-8，保留表头；
2. 日期统一为 `YYYY-MM-DD`，多值字段用分号；
3. 不改变小数精度和单位；
4. 用校验脚本检查枚举、唯一性和引用。

### 图片

1. 记录拍摄对象、日期、产品、粒度/批次和授权；
2. 删除不必要的 EXIF 和可识别客户/员工信息；
3. 标签图片遮盖客户名、订单号、条码和联系方式；
4. 只有获得外部使用授权的图片才可标记可营销。

### Markdown

1. 用中文记录内部说明，技术英文保留原文；
2. 每项结论引用 `evidence_id`，不要粘贴敏感原文；
3. 未批准内容明确标记 `pending`；
4. 保持相对链接和 UTF-8 编码有效。

## 6. Codex提取后的人工复核

Codex/OCR 的提取结果只是工作草稿。责任部门必须对照原件复核数据值、单位、小数点、测试方法、粒度、批次、有效期和保密级别。Codex 不得作为批准人，也不得基于公开行业值补齐空白。

## 7. 获批后的更新范围

批准后由单独任务评估并更新：

1. `product-data/product-master-data.json`：数据、状态、证据和 `last_updated`；
2. `product-data/missing-information.md`：对应缺口状态和汇总；
3. `product-data/product-comparison.md`、术语或模板（如受影响）；
4. `market-positioning/`：产品定义、分级、命名、应用边界或价值主张；
5. `PROJECT_STATUS.md`、`ROADMAP.md`：仅当阶段或依赖发生变化；
6. `DECISIONS.md`：形成关键决定时新增决策记录。

## 8. 禁止直接回填

未完成证据登记、责任部门核实和授权批准的资料，不得直接写入 `product-data/product-master-data.json`。收到文件不等于数据已批准；单批 COA 不等于长期保证值；内部批准也不自动等于允许公开营销。
